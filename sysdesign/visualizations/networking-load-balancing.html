Load balancing + service mesh

L4 vs L7, the algorithms, sticky sessions, sidecar service mesh, layered architecture. Pick the right LB layer for the failure you care about.

1. L4 vs L7 load balancing

The fundamental split: does the load balancer understand the protocol inside the connection, or just forward bytes?

L4 -- Transport layer (TCP/UDP)

Sees only IP addresses and port numbers. Forwards raw bytes without inspecting content. Cannot parse HTTP, route by path, or rewrite headers.

  • AWS NLB
  • HAProxy (TCP mode)
  • IPVS / LVS
  • Google Maglev

L7 -- Application layer (HTTP/gRPC)

Terminates TLS, parses HTTP, reads headers/path/body. Can route by content, retry failed requests, rewrite URLs, inject headers.

  • AWS ALB
  • NGINX
  • HAProxy (HTTP mode)
  • Envoy
Click "Run demo" to see L4 forwarding raw bytes vs L7 parsing and routing by path.
DimensionL4L7
SeesIP + portHTTP method, path, headers, body
TLSPass-through (end-to-end)Terminates at LB (SSL offload)
RoutingIP/port hash, round-robinPath, host, header, cookie
RetryCannot (bytes already sent)Per-request retry to different backend

Takeaway: L4 = fast and dumb (good for TCP-native workloads, WebSocket, RPC frameworks that handle their own retries). L7 = smart and routable (good for REST APIs, mixed apps, retry policies, canary deploys). Choose based on whether you need content-aware routing.

3. Sticky sessions

Sticky sessions pin a client to a specific backend. Three mechanisms, each with different trade-offs.

Select a stickiness mechanism and click "Run demo" to see how users are pinned to backends.

When you NEED stickiness

  • App stores per-user state in memory (anti-pattern, but real)
  • Long-lived connections (WebSocket must hit the same backend)
  • Cache locality optimization (not strict, but beneficial)

When you do NOT

  • Stateless services -- let the LB pick freely
  • Session state in external store (Redis, DB)
  • JWT/token-based auth (no server-side session)
Takeaway: Stickiness has a cost: uneven load distribution and brittleness to backend failure. When a pinned backend dies, all its sticky clients lose their sessions. Use only when state requires it -- and prefer externalizing state instead.

4. Health checks

Health checks determine which backends receive traffic. Two complementary approaches, plus two operational safeguards.

Click "Run demo" to watch Backend 3 flap: passive detection ejects it, active probe re-admits it, traffic ramps gradually via slow start.
MechanismHowProCon
ActiveLB sends GET /health every N secondsCatches backends that stopped servingHealth endpoint must be cheap; hitting DB causes cascades
PassiveLB watches real traffic error ratesCatches degraded backends active checks missNeeds real traffic; new backends have no signal
Slow startRamp traffic 10% -> 25% -> 50% -> 100%Prevents cold-start cascadeSlower recovery
Outlier detectionEject if error rate >> peersAutomatic, no manual thresholdNeeds enough peers to detect outliers
Takeaway: Health checks must be cheap AND reflect real serving capacity. A /health endpoint that hits the database causes cascading outages when the DB is the thing that is failing. Use both active + passive together; slow-start on recovery; outlier detection as the safety net.

5. Service mesh -- sidecar pattern

Move cross-cutting concerns (mTLS, retries, circuit breakers, observability) out of application code and into infrastructure.

Click "Show traffic flow" to see mTLS-encrypted east-west traffic. Then "Canary deploy" to split traffic between v1 and v2 via the mesh.
Takeaway: Service mesh = move cross-cutting concerns out of app code into infrastructure. Worth it when you have many services in many languages. Overkill for 3-service teams. The trade-off: extra hop per request (latency), sidecar resource overhead, operational complexity.

6. Ingress vs API gateway vs edge LB

These are not alternatives -- they are layers. Each handles a different scope of responsibility as a request travels from user to pod.

Takeaway: These are not alternatives -- they are layers. Edge LB at the perimeter for DDoS and caching; API Gateway for auth + business policy; Ingress for k8s cluster entry; mesh for east-west pod traffic. In an interview, name the layer that matches the concern being discussed.
