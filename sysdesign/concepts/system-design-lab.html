§ 99  Interview frameworks

The reusable spine.

Every problem on this page maps onto the same four-step structure. Memorise the structure; the problem-specific content fills itself in.

The four steps

  1. Clarify — functional + non-functional. Latency targets, consistency level, scale, geography. Write them down.
  2. Estimate — DAU, QPS (peak = 3× average), storage per year, bandwidth. Five lines of math, on the board.
  3. Design — API contract first, then data model, then boxes-and-arrows. Mark which paths are async; pick the partition key out loud.
  4. Deep dive — let the interviewer pick the component (or pick the gnarliest one yourself). Discuss failure modes, dedup, retries, tail latency.

Back-of-envelope formulas

QPS = DAU × actions/user ÷ 86400

Peak QPS = avg_QPS × 3 (or 5× for retail)

Storage = items × size × RF × retention

Bandwidth = QPS × payload_size

Read amp = fan-out factor (followers, members)

Cache hit ratio — design for > 90%; otherwise it’s not really a cache.

The “at 10x” question

Almost every staff loop ends with: “What would you do differently if traffic 10x’d?” The interviewer wants to know whether you understand which parts of your design are the bottleneck. Have an answer ready: (a) identify the partition that would melt first, (b) name the cheap mitigation (caching, sharding by a finer key), (c) name the structural change you’d make if cheap mitigations ran out (split service, change consistency model, push to a different storage engine).

If you can’t name what melts first at 10x, you don’t understand your own design well enough to claim it’s production-ready.

Universal patterns worth memorising

  • Idempotency keys — client-supplied, dedup at the edge, write-once at the store.
  • Outbox pattern — durable async dispatch; write event to the same DB transaction, drain to the queue.
  • Saga — long-running multi-service transaction with compensating actions; replaces 2PC where 2PC won’t scale.
  • CQRS — separate write model (normalised) from read model (denormalised, often pre-joined). Eventual consistency between them.
  • Backpressure — bounded queues, reject early, let upstream slow down. Unbounded queues are bombs.
  • Hedged requests — fire 2 reads, take the first; cuts tail latency. Costs ~5-10% extra traffic.
  • Bulkheads + circuit breakers — isolate failure domains, fail fast, recover in seconds not minutes.
