Bipartite ≠ "2 connected components"

A common conflation: "bipartite" means the graph splits into two pieces. It does not. Bipartite means the nodes can be split into two sets such that every edge crosses between them — a 2-coloring property of the whole graph. The number of connected components is unrelated.

Below, six small graphs labeled by their component count and their bipartite status. Notice that the two columns vary independently — every combination is realizable.

The rule: a graph is bipartite if and only if it has no odd-length cycles. Components don't matter — the algorithm just runs BFS-coloring on each component independently and the graph is bipartite iff every component colors cleanly.

Why BFS coloring works

Pick any uncolored node, color it A, push to queue. Pop a node N, assign the opposite color to each unvisited neighbor and push them. If you encounter an already-colored neighbor whose color matches N, you've found two paths of different parity to the same node — that's an odd cycle, and the graph isn't bipartite.

The "opposite color of my parent" rule means BFS layers alternate A-B-A-B by depth. A back-edge to the same layer is an odd cycle; a back-edge to the previous layer is an even cycle. The algorithm catches the first kind and shrugs at the second.
