LIS — Patience Sort O(n log n)

Maintain tails[i] = smallest possible tail value of any increasing subsequence of length i+1. For each num, binary-search for the leftmost slot j with tails[j] ≥ num and replace it — or append if num exceeds every tail.

Why tails stays sorted

A length-k+1 increasing subsequence has a length-k prefix whose tail is strictly less than its length-k+1 tail. So the smallest length-k+1 tail is ≥ the smallest length-k tail. The array is sorted by construction → binary-searchable.

Why replacing improves things

If we find an existing length-j+1 IS ending in tails[j], and the current num < tails[j], then num is a better tail for length-j+1 — easier to extend later. Shorter tails dominate.

⚠ Frankenstein warning

tails is NOT the actual LIS — only a bookkeeping array. Intermediate states can look like sequences that never appeared in the input. Example: on [3, 1, 4, 1, 5, 9, 2, 6] the final tails = [1, 2, 5, 6], but that exact sequence is not a subsequence of the input (the 5 at index 4 comes before the 2 at index 6). The length 4 is still correct — e.g. the real LIS [1, 4, 5, 9] or [1, 4, 5, 6]. To reconstruct the actual subsequence you need a separate predecessor array.
