Serialize / Deserialize — Null Markers Encode Tree Shape

A single traversal alone can't recover a tree's shape — that's why most reconstruction problems need two traversals (pre+in, post+in). But a traversal with null markers is invertible: the nulls tell you "no child here, come back up." One walk encodes; the reverse walk rebuilds.

Example tree: [1, 2, 3, null, null, 4, 5]. Pre-order with # for null → target output: 1,2,#,#,3,4,#,#,5,#,#.

// Pre-order DFS with null markers — the canonical template public String serialize(TreeNode root) { StringBuilder sb = new StringBuilder(); ser(root, sb); return sb.toString(); } private void ser(TreeNode n, StringBuilder sb) { if (n == null) { sb.append("#,"); return; } sb.append(n.val).append(","); ser(n.left, sb); ser(n.right, sb); } // Deserialize mirrors it: a shared token queue, same recursion shape. // The call stack tracks where in the tree we are — no index bookkeeping. public TreeNode deserialize(String data) { Deque<String> tokens = new ArrayDeque<>(Arrays.asList(data.split(","))); return des(tokens); } private TreeNode des(Deque<String> tokens) { String t = tokens.poll(); if (t.equals("#")) return null; TreeNode n = new TreeNode(Integer.parseInt(t)); n.left = des(tokens); // recursion pairs calls with tokens automatically n.right = des(tokens); return n; }
Why this is invertible. Without the # markers, the string 1,2,3,4,5 could correspond to many different trees — there's no way to know where one subtree ends and another begins. The nulls act as terminators: when the deserializer sees #, it knows "this subtree is empty, return up a level." That's the same thing the serializer's recursion did on its way down. One token per recursive call — symmetric by construction.
